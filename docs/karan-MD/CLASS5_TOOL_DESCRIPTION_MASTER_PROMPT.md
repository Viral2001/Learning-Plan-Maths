# MASTER PROMPT: CLASS 5 MATHS INTERACTIVE TOOL DESCRIPTION GENERATOR

(Saved verbatim from the user's message of 17 Nov 2026. Section 9 is the format every Class 5 tool description follows.)

## 1. UNDERSTAND THE CHAPTER FIRST
Before writing any tool descriptions:
- Carefully study the complete chapter content, including its concepts, examples, activities, illustrations, stories, numbers and learning objectives.
- Understand what students are expected to learn from each section.
- Identify the most suitable concepts that can benefit from interactive learning.
- Keep every tool conceptually accurate and appropriate for Class 5.
- Do not introduce unrelated concepts, advanced mathematics or unnecessary activities.
- Preserve the original mathematical meaning, examples and context provided in the supplied chapter material.
Each tool should focus on one clear mathematical learning objective.

## 2. INTERACTIVE DOER-BASED LEARNING
Every tool must be an active learning experience, not a passive presentation.
Students should perform meaningful actions such as:
- Dragging and dropping objects.
- Arranging, grouping and sorting elements.
- Building numbers, shapes, patterns and models.
- Splitting and combining objects.
- Comparing quantities and mathematical relationships.
- Moving objects along number lines.
- Rotating, resizing and manipulating shapes.
- Measuring, counting, shading and constructing.
- Experimenting with different possibilities.
Choose interactions according to the mathematical concept. Do not force unnecessary drag-and-drop interactions into every tool. The student should be the main participant throughout the activity.

## 3. OUTSTANDING VISUAL EXPERIENCE
Visual quality is a major priority but we cant ignore the concept.
Design tools that feel like polished, interactive educational games rather than basic HTML worksheets.
Use appropriate visual approaches such as:
- Attractive 2D illustrations and 3D objects.
- Realistic, colourful learning manipulatives.
- Animated mathematical objects.
- Interactive environments and miniature scenarios.
- Visually appealing number lines, grids, charts and models.
- Smooth transitions and meaningful animations.
- Layered visual elements that make mathematical relationships easy to understand.
Use real-world objects wherever they improve conceptual understanding.
Every tool should have its own visual identity based on its mathematical concept. Do not force a single theme across different tools. Avoid plain screens containing only text, buttons, static diagrams or basic shapes when a more engaging visual representation is possible.

## 4. SIMPLE AND CHILD-FRIENDLY UI
Design specifically for 10-11-year-old students.
- Keep the interface intuitive and easy to operate independently.
- Use large interactive objects and clearly visible controls.
- Keep instructions short, simple and conversational.
- Give maximum screen space to the main interactive activity.
- Avoid unnecessary menus, settings, sidebars and information panels.
- Avoid asking students to enter too many numerical values.
- Prefer direct manipulation and visual interactions over lengthy text inputs.
- Make every important action discoverable without complicated instructions.
The child should understand what to do almost immediately.

## 5. FIXED SCREEN FRAME
Maintain a consistent basic layout across all tools.
Top bar:
- Small tool title.
- Phase indicators only when the tool uses multiple phases.
Instruction area:
- One short instruction line above the main activity.
Main stage:
- Approximately 70% of the screen.
- The primary interactive visual should occupy most of the available space.
Bottom controls:
- Maximum 2-3 large, useful buttons.
- Examples: Reset, Check, Next, Hint.
Strict requirements:
- No sidebars.
- No unnecessary panels.
- No settings menus.
- No excessive instructions.
- Everything should fit on one screen without scrolling on both laptops and tablets.
Adapt the internal arrangement according to the activity while maintaining this common screen structure.

## 6. LEARNING FLOW
One concept per tool, built from the textbook's own activities, numbers and story.
Never show NCERT, chapter or page references. No side panels.
TOOL STRUCTURE (top-bar pills)
1. Activities 1...n: the textbook's activities in the book's order, each a small step up.
   The first 1-2 activities give more help (labels, guides). Later ones remove it (Learn -> Practice).
2. Practice / Table (optional): several quick items using the same action.
3. (star) Challenge(s): the textbook's harder question or a twist on the same concept.
4. Finish -> End screen: "Well done!" + 2-3 Remember lines (the rules the child discovered)
   + one Think and talk question + Start again.

EVERY ACTIVITY FOLLOWS THE SAME LOOP
1. GOAL: one short instruction line on the card, plus goal chip(s) on the stage.
2. DO: the child handles the object in a photo scene (tiles, marker, counters, horses, boat...).
3. GUESS: before the result, the child predicts or commits (bigger/smaller/same, closer end, which side changes).
4. RESULT + WHY: the visual animates the answer, and the feedback strip gives ONE line with the actual numbers.
5. DONE: the goal chip turns green, the pill gets a tick, and Next unlocks.

FEEDBACK AND HINTS
- Wrong -> red strip + small shake + one line naming the misconception and what to look at
  (e.g. "An empty place is not a zero: use the 0 tile").
- Every tool has a Hint button with up to 3 levels: words -> visual clue -> almost the answer.
- No scores. Progress = pills with a tick and green goal chips.

FRAME (identical in every tool)
- Top bar: Title - Activity pills (star challenges)
- Stage: photo scene + goal chips - Card: instruction line -> feedback strip -> one button row
- Everything fits on one screen. Touch and mouse both work.

## 7. MEANINGFUL FEEDBACK AND ENGAGEMENT
Every student action should produce an immediate visual response.
Examples:
- Objects move, snap or rearrange naturally.
- Mathematical relationships become visually clear.
- Correct actions trigger a gentle bounce or positive animation.
- Incorrect actions provide friendly hints.
- Students can retry without unnecessary restrictions.
- Important discoveries are highlighted visually.
Use encouraging language.
Never make students feel punished for incorrect answers.
Avoid traditional marks, percentages and scoreboards. Show progress through small stars, dots or visual completion indicators where appropriate. Use confetti only for meaningful final achievements, not after every small action.
Optional soft sound effects can be included with a visible mute control.

## 8. VARIETY AND ORIGINALITY ACROSS TOOLS
Avoid repeating the same interaction pattern across every tool.
For example:
- A fraction tool may use movable fraction pieces.
- A geometry tool may use interactive 3D construction.
- A measurement tool may use virtual measuring instruments.
- A pattern tool may use sequence-building puzzles.
- A number-line tool may use movement and jumping.
- An area tool may use interactive grids and boundary construction.
These are examples, not fixed templates.
Select the best interaction, environment and visual representation for each individual concept.
Every tool must provide a distinct learning experience and add genuine educational value.
Do not turn every activity into a quiz or generic game.

## 9. TOOL DESCRIPTION WRITING FORMAT
Write every tool description in this exact structure. Be specific: state the exact numbers,
objects, text and behaviour. Never write vague lines such as "make it interactive",
"add animations" or "use colourful visuals". Describe what the student sees and exactly
what happens when they act.

A. TOOL TITLE
- Short, child-friendly and tied to the concept (e.g. "Digit Swap Challenge", "Rounding Number Line").

B. TOOL INFO
- Tool ID: [e.g. M1.S5.T5.C12.2D1] (in the code only, never on screen)
- Tool type: Concept-activity / Exploration / Puzzle
- Textbook source: chapter, the textbook activity it is built from, and the numbers used
  (for the developer only; nothing from this appears on screen)

C. LEARNING OBJECTIVE
- One sentence: the single concept the student will understand.
- Out of scope: related ideas this tool must NOT teach.

D. TOOL DESCRIPTION

1. Opening Screen
   - What the stage shows on first load (photo scene, objects, numbers).
   - The exact first instruction line on the card.
   - What the student is invited to touch first.

2. Scene and Objects
   - Background photo or scene (describe it so an image can be made or found).
   - Every object on the stage: what it looks like, its size and where it sits
     (tiles, marker, counters, horses, number line, labels).
   - Goal chips shown on the stage.
   - Do NOT describe frame colours, fonts or the top bar; the common frame sets these.

3. Main Interaction
   - Exactly what the student can tap, drag, place, swap or slide, and what each action does.
   - Limits (e.g. "max 3 horses per stall", "only one item in the boat").
   - Undo / Reset / Clear behaviour.

4. Activities (one block per pill: Activity 1...n, Table/Practice, star Challenge 1...n)
   For EACH activity give:
   - Goal line (exact text) and goal chip text
   - Starting numbers or setup
   - What the student does
   - Guess step: the prediction asked before the result (if any)
   - Correct result: what animates, plus the exact one-line "why" with the actual numbers
   - Help level: guided (labels, guides shown) or independent (help removed)

5. Mathematical Understanding
   - How doing the action leads the student to the rule (what they notice, compare or count).
   - The rule(s) they should be able to say at the end.

6. Feedback and Hints
   - Correct: what turns green, what animates, the exact success line.
   - Common mistakes: list each likely mistake -> its exact message + what gets highlighted.
     (e.g. "Empty place left -> 'An empty place is not a zero: use the 0 tile.' The empty slot pulses.")
   - Hint button, 3 levels: (1) words -> (2) a visual clue on the stage -> (3) almost the answer.
   - Edge cases: zeros, a number exactly in the middle, the same digits, and so on.

7. Ending
   - Star Challenge(s): the harder task and its success condition.
   - End screen: "Well done!" + 2-3 Remember lines (exact text) + one Think and talk question (exact text).

8. Assets and Language
   - List of images needed (scene, objects), with a short description of each.

## 10. GENERAL DESIGN AND TECHNICAL EXPECTATIONS
The descriptions should guide development towards:
- A single self-contained HTML experience.
- Responsive layouts for laptops and tablets.
- Both touch and mouse interaction.
- Smooth and lightweight animations.
- Clean, reliable and maintainable implementation.
Prefer CSS illustrations, SVG graphics, Canvas and JavaScript-generated objects where suitable.

## 11. STRICT CONTENT RULES
- Use the supplied chapter material as the content boundary.
- Teach only the assigned concept in each tool.
- Keep all numbers, examples and mathematical situations appropriate to the chapter.
- Use simple English that a 10-year-old can understand.
- Keep on-screen instructions to one short line wherever possible.
- Never expose internal tool IDs or development metadata in the student interface.
- Do not display textbook references, page numbers or source references.
- Do not add unrelated stories, concepts or mathematical challenges.
- Do not overcomplicate a simple concept.

## FINAL QUALITY STANDARD
Before finalising each tool description, verify:
- Is the mathematical concept clear and accurate?
- Is the experience appropriate for Class 5?
- Is the activity genuinely hands-on and interactive?
- Are the visuals attractive, detailed and conceptually relevant?
- Does every interaction have a learning purpose?
- Is the interface simple and intuitive?
- Does the tool have its own distinct identity?
- Is the activity engaging without unnecessary complexity?
- Can a developer build the experience directly from the description?

FINAL OBJECTIVE:
Create visually exceptional, conceptually accurate, highly interactive and child-friendly Maths learning tools.
Students should not feel that they are completing another worksheet. They should feel that they are playing, exploring, building and discovering mathematics themselves.
